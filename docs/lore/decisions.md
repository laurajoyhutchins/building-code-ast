# Decisions and constraints

> Generated by LORE from reviewed repository knowledge. This document is non-authoritative.

## Adopt composable condition expressions for provision AST 0.3.0

The approved 0.3.0 design replaces flat comparison tuples with a required nullable recursive condition expression while keeping parser output conservative and provenance-preserving.

- Replace ProvisionAst.conditions with ProvisionAst.condition, whose value is null, one comparison, an all_of group, or an any_of group.
- Provision AST 0.3.0 is intentionally incompatible with 0.2.0.
- Mixed, grouped, or malformed candidate chains fail closed with deterministic diagnostics and no partial semantic output.

Evidence:

- `docs/superpowers/specs/2026-08-01-composable-condition-expressions-design.md`

Related: `component.provision-parser`, `component.validation`

## Keep compiler representations staged

Publication structure, provision semantics, cross-reference resolution, reviewed normalization, and project evaluation remain distinct representations.

- Do not place modality, applicability, actions, compliance conclusions, or professional interpretation in the document structure AST.
- Document and provision ASTs are versioned independently.
- Later stages retain links to earlier source evidence.

Evidence:

- `docs/architecture.md`
- `src/building_code_ast/document_model.py`
- `src/building_code_ast/parser.py`

Related: `component.document-structure`, `component.provision-parser`

## Preserve provenance before interpretation

Exact source identity, original text, spans, deterministic identities, and diagnostics are mandatory before semantic claims are trusted.

- Treat provenance and uncertainty as first-class contract data rather than incidental parser metadata.
- Derived nodes carry exact evidence spans and unsupported language remains visible through diagnostics.
- Model-assisted extensions must satisfy the same deterministic contracts.

Evidence:

- `docs/architecture.md`
- `src/building_code_ast/document_validation.py`
- `src/building_code_ast/validation.py`

Related: `component.document-structure`, `component.provision-parser`, `component.validation`

## Respect corpus and legal safety boundaries

Repository contents and outputs must not imply redistribution rights, authoritative interpretation, or project compliance.

- Only project-authored software, documentation, schemas, and synthetic fixtures belong in the repository unless a source has been reviewed for lawful inclusion.
- Do not commit proprietary model-code text, standards text, licensed commentary, or bulk source material for convenience.
- Label parsed output as non-authoritative and preserve source provenance.
- Keep jurisdiction resolution, parsing, interpretation, and professional judgment as separate responsibilities.
