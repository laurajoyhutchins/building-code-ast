# Architecture and components

> Generated by LORE from reviewed repository knowledge. This document is non-authoritative.

## Document structure AST

Represents publication structure, deterministic node identity, and exact source provenance before semantic interpretation.

- Represent document, chapter, section, subsection, paragraph, list, definition, table, heading, note, footnote, and unsupported nodes.
- Derive stable node identity from source artifact, edition, node type, and structural locator.
- Preserve exact source spans and recursively validate containment, uniqueness, and identity.

- `src/building_code_ast/document_model.py`
- `src/building_code_ast/document_io.py`
- `src/building_code_ast/document_validation.py`
- `docs/reference/document-ast.md`

Related: `repository.building-code-ast`

## Provision parser

Parses a deliberately bounded family of synthetic code-style provisions into semantic AST nodes while preserving unsupported or ambiguous language.

- Recognize requirement, prohibition, permission, subject, numeric condition, action, and section-reference exception structures.
- Preserve exact original input and evidence spans for recognized structures.
- Emit diagnostics rather than silently guessing beyond the supported grammar.

Evidence:

- `src/building_code_ast/parser.py`
- `src/building_code_ast/model.py`
- `src/building_code_ast/validation.py`
- `README.md`

Related: `repository.building-code-ast`

## Validation and contracts

Enforces schema, identity, source-span, containment, and malformed-input invariants for both public AST representations.

- Prove that source spans round-trip to exact source text.
- Reject duplicate, malformed, out-of-bounds, or identity-inconsistent structures.
- Keep JSON Schema projections aligned with runtime contracts.
