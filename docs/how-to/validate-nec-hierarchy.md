# Validate inferred NEC hierarchy

Use this procedure to compare locally generated NEC 2017 ArticleSeed hierarchy with an independently prepared clause hierarchy. The comparison is a parser-development check. It does not copy the reference hierarchy into parser output and does not make the reference a production dependency.

## Inputs

You need:

- one or more private ArticleSeed JSON files generated by `scripts/ingest_nec_2017.py`;
- a local CSV containing the columns `clause_id`, `clause_title`, and `parent`;
- a private output location for the conformance report.

Laura's existing reference is stored in the junk-drawer repository at:

```text
nec/csv/nec-2017-clauses.csv
```

Materialize that repository locally or otherwise obtain the CSV through an authorized local workflow. Do not add the reference file, ArticleSeed files, the NEC PDF, extracted prose, or generated page images to this repository.

## Run the comparison

From the Building Code AST repository root:

```bash
PYTHONPATH=src python scripts/check_nec_2017_hierarchy.py \
  --article-seed generated-private/nec-2017/article-90.json \
  --article-seed generated-private/nec-2017/article-100.json \
  --article-seed generated-private/nec-2017/article-110.json \
  --oracle /path/to/junk-drawer/nec/csv/nec-2017-clauses.csv \
  --report generated-private/nec-2017/hierarchy-conformance.json \
  --strict
```

Repeat `--article-seed` for each converted Article. The command filters the reference to exactly those Articles before comparison. Duplicate ArticleSeed inputs are rejected.

Without `--strict`, the command writes the report and returns success even when mismatches exist. With `--strict`, any mismatch returns exit status `1`, making the command suitable for local gates and private evaluation workflows.

## Report contents

The JSON report contains:

- compared Article numbers;
- input basenames, not absolute paths;
- expected and inferred structural-record counts;
- exact-match count;
- mismatch counts by class;
- locator-level mismatch details.

The report does not copy ArticleSeed `source_text`, source spans, PDF coordinates, extracted NEC prose, artifact hashes, or edition hashes.

## Mismatch classes

- `missing-locator`: the reference contains a clause the parser did not infer.
- `unexpected-locator`: the parser inferred a clause absent from the reference.
- `duplicate-expected-locator`: the reference contains the same canonical locator more than once.
- `duplicate-actual-locator`: the parser emitted the same canonical locator more than once.
- `parent-mismatch`: the locator exists in both trees but has a different parent.
- `title-mismatch`: the locator exists in both trees but its normalized title differs.
- `depth-mismatch`: the locator exists in both trees but its structural depth differs.
- `order-mismatch`: the expected and inferred locator sequences diverge.

Treat mismatches as evidence for parser development, not permission to force output to match the reference. Add a synthetic regression that represents the observed structural pattern, improve the parser rule, and rerun the private comparison.

## Architectural boundary

The reference answers, “What hierarchy should the 2017 parser reproduce?” The PDF-derived ArticleSeed answers, “What text and coordinates support each inferred node?” Keeping those roles separate allows the same parser to process later NEC editions without requiring a prebuilt hierarchy while still benefiting from the substantial 2017 structure work already completed.
